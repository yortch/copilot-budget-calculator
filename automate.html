Before you start

All endpoints below require enterprise admin or billing manager permissions, and the enterprise must be on the enhanced billing platform with AI credit paid usage enabled. Use the selector below to switch every command on the page between GitHub CLI and cURL.

Git Bash tip for gh api The GitHub CLI examples use JSON via --input - <<JSON so placeholders like $USERNAME expand correctly in Git Bash, and include --silent to avoid parse issues like unexpected end of JSON input on empty responses. Remove --silent if you want the response body (for example, to capture the new budget id).

Authentication

GitHub CLI uses your existing gh auth login session, so no token appears in the command. cURL requires a token (classic PAT with manage_billing:enterprise, or a fine-grained token / GitHub App with enterprise billing permissions) supplied as a Bearer header — store it in an environment variable rather than pasting it inline.

Placeholders used throughout

PlaceholderMeaning
ENTERPRISEThe slug of your enterprise (from the enterprise URL)
GH_TOKENEnvironment variable holding your access token (cURL only)
USERNAMEA GitHub login (for individual budgets / alert recipients)
COST_CENTER_IDThe UUID returned when you create a cost center

1Create an enterprise budget

When to use Set one enterprise-wide ceiling on metered AI credit spend as a financial backstop. This is the broadest control — it governs total enterprise metered charges across every user and cost center once the shared pool is exhausted. Use it to guarantee the bill never exceeds a hard number. Enable prevent_further_usage to make it a hard stop (off by default in the UI).
  • Reference: Enterprise budget — Budgets for usage-based billing
  • API: Create a budget
POST /enterprises/$ENTERPRISE/settings/billing/budgets
gh api --silent \
  --method POST \
  -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  "/enterprises/$ENTERPRISE/settings/billing/budgets" \
  --input - <<JSON
{
  "budget_type": "BundlePricing",
  "budget_product_sku": "ai_credits",
  "budget_scope": "enterprise",
  "budget_amount": 50000,
  "prevent_further_usage": true,
  "budget_alerting": { "will_alert": true, "alert_recipients": ["$USERNAME"] }
}
JSON
POST /enterprises/$ENTERPRISE/settings/billing/budgets
curl -L \
  -X POST \
  -H "Accept: application/vnd.github+json" \
  -H "Authorization: Bearer $GH_TOKEN" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  https://api.github.com/enterprises/$ENTERPRISE/settings/billing/budgets \
  -d '{
    "budget_type": "BundlePricing",
    "budget_product_sku": "ai_credits",
    "budget_scope": "enterprise",
    "budget_amount": 50000,
    "prevent_further_usage": true,
    "budget_alerting": { "will_alert": true, "alert_recipients": ["$USERNAME"] }
  }'

budget_amount is in whole US dollars. The enterprise scope needs no budget_entity_name.

2Create a default User-Level Budget (ULB)

When to use Apply the same per-user AI credit cap to every user at once — without creating a budget per person. This is the recommended baseline control: it stops any single user from draining the shared pool or running up unbounded metered charges. Use the calculator's Universal ULB recommendation for the amount. The multi_user_customer scope creates one budget that GitHub enforces per user; prevent_further_usage must be true (ULBs are always a hard stop).
  • Reference: User-level budget — Budgets for usage-based billing
  • API: Create a budget · Get per-user states

  --method POST \
  -H "Accept: application/vnd.github+json" \
  -H "Content-Type: application/json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  "/enterprises/$ENTERPRISE/settings/billing/budgets" \
  --input - <<JSON
{
  "budget_type": "BundlePricing",
  "budget_product_sku": "ai_credits",
  "budget_scope": "multi_user_customer",
  "budget_amount": 60,
  "prevent_further_usage": true,
  "budget_alerting": { "will_alert": true, "alert_recipients": ["$USERNAME"] }
}
JSON
POST /enterprises/$ENTERPRISE/settings/billing/budgets
curl -L \
  -X POST \
  -H "Accept: application/vnd.github+json" \
  -H "Authorization: Bearer $GH_TOKEN" \
  -H "X-GitHub-Api-Version: 2022-11-28" \

The multi_user_customer and user scopes are only valid when budget_product_sku is ai_credits or premium_requests. Inspect per-user consumption later with the /budgets/{budget_id}/user-states endpoint.

3Create an individual user budget

When to use Override the default ULB for specific power users who legitimately need more headroom (or, occasionally, less). A user-scoped budget takes precedence over the default multi_user_customer ULB for that login. Create one of these per named power user instead of raising the default ULB for everyone. Remember: a higher personal ULB does not bypass the enterprise budget — lowest remaining headroom still wins. prevent_further_usage must be true.

  • API: Create a budget

4Create a cost center & cost center budget

When to use Group users, teams, organizations, or repositories into a cost center when you want to track and cap spending for a financial entity (a department, business unit, or project team) separately from the rest of the enterprise. Cost centers also enable the "excluded cost center" pattern for power-user teams that must never be blocked by the enterprise budget. The steps below create the cost center, populate it, and then attach budgets.
  • Reference: Controlling and tracking costs at scale · Cost center allocation for different products
  • API: Create a budget

4.1 — Create the cost center

POST /enterprises/$ENTERPRISE/settings/billing/cost-centers
gh api \
  --method POST \
  -H "Accept: application/vnd.github+json" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  /enterprises/$ENTERPRISE/settings/billing/cost-centers \
  -f name='Engineering'
# → response includes the new cost center "id" (a UUID). Save it as $COST_CENTER_ID.
POST /enterprises/$ENTERPRISE/settings/billing/cost-centers
curl -L \
  -X POST \
  -H "Accept: application/vnd.github+json" \
  -H "Authorization: Bearer $GH_TOKEN" \
  -H "X-GitHub-Api-Version: 2022-11-28" \
  https://api.github.com/enterprises/$ENTERPRISE/settings/billing/cost-centers \
  -d '{ "name": "Engineering" }'
# → response includes the new cost center "id" (a UUID). Save it as $COST_CENTER_ID.

4.3 — Assign enterprise teams to the cost center New · Jun 25, 2026

When to use Assign a whole enterprise team instead of listing members one by one. Team membership flows into the cost center and stays current automatically as people join or leave — ideal for managing membership via your IdP without touching organization scope. Managing budgets you create

Every POST to /budgets returns the new budget's id. Use these read/update/delete endpoints to manage them afterward:

  • GET /enterprises/$ENTERPRISE/settings/billing/budgets — List all budgets (filter with ?scope=enterprise|cost_center|user|multi_user_customer|multi_user_cost_center)
  • PATCH /enterprises/$ENTERPRISE/settings/billing/budgets/$BUDGET_ID — Update a budget
  • DELETE /enterprises/$ENTERPRISE/settings/billing/budgets/$BUDGET_ID — Delete a budget
  • GET /enterprises/$ENTERPRISE/settings/billing/cost-centers — Budgets REST API to discover existing $COST_CENTER_ID values
